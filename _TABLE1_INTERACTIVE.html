지표의 기준

재투영과 3D 위치 오차를 구분

“전체 재투영”은 무엇을 합치나?

각 방법이 사용하는 모든 held-out 관측의 코너를 카메라 영상에 다시 투영한 뒤, 관측 코너와의 2D 픽셀 잔차를 한꺼번에 pooling한 component-wise RMSE입니다.

RMSE = √(Σ(Δu² + Δv²) / (2 × N코너))

보드 706코너와 큐브 228코너를 쓰는 방법은 총 934코너가 기준이며, board/cube RMSE의 단순 평균이 아닙니다. A0·B3는 보드만, B2는 큐브만 포함합니다. 모든 변환은 train에서 동결되고 test-time refit은 없습니다. 재투영 오차는 카메라 영상의 관측량인 px로만 보고합니다.

고정↔손목+FK 경로 불일치 · mm

동일 held-out event에서 고정카메라 묶음이 찾은 큐브 중심과 손목카메라+로봇 FK 경로가 찾은 큐브 중심 사이의 3D 거리 RMSE입니다.

√mean(‖t_fixed-avg − t_robot-FK+eih‖²)

현재 공통 mask가 지원하는 3개 event unit(sets 5·9·11) 기준의 e_e2e 병진값입니다. FK 경로가 들어가지만 FK를 정답으로 둔 오차가 아니며, 외부 GT가 없으므로 두 경로 사이의 내부 폐쇄 불일치로만 해석해야 합니다.

!
교수님 피드백 반영: 재투영 오차의 예측깊이 기반 mm 환산은 삭제하고 raw distorted-pixel RMSE만 남겼습니다. 모든 방법에 같은 338 corners를 적용한 공통-pose 평가와 함께, 카메라 A의 측정-only PnP cube pose를 카메라 B에 넘겨 실제 B 코너와 비교하는 9쌍·18방향 pixel-transfer를 공통 1차 지표로 계산합니다.
교수님 피드백별 코드·데이터 답변

명칭: e_cross는 통상적인 고정카메라 간 큐브 위치 일관성입니다. 각 카메라의 PnP 큐브 pose를 base로 옮긴 뒤 모든 카메라 쌍의 큐브 중심 거리를 RMSE 집계합니다. FK·손목카메라·외부 GT는 쓰지 않습니다.

공통 기준: 공통-pose 평가는 cam0·1·3, events 29·53·65, 18 observations/338 corners를 모든 8개 실행 방법에 동일하게 적용합니다. Pixel-transfer와 path 평가는 같은 held-out cube 관측에서 9 fixed-camera pairs/18 directions/3 fixed↔gripper units를 모든 방법에 적용하므로 A0/B3 값은 evaluation-only이며 학습에 큐브를 썼다는 뜻이 아닙니다.

baseline 두 종류: 알고리즘 구성요소 비교인 A0–B3는 held-out을 제외한 동일 train-only reference state에서 시작하고 선언된 marker/FK/freeze treatment만 적용합니다. 따라서 −board/−cube는 목적함수에서의 제거를 뜻합니다. 마커 시스템 비교는 별도 end-to-end 표에서 각 modality로 초기화부터 다시 수행합니다. 두 실험 모두 split·K/D·raw 검출·solver·seed·공통 평가는 같습니다.

Step3 동일성: Step3는 별도 최종 solver를 갖지 않고 Table 1 runner의 baseline-only 모드를 호출합니다. A3도 다른 통합 행과 같은 canonical corner solver를 직접 사용하며, FK cube pose만 freeze mask로 고정합니다.

통합식: 카메라별 K,D는 상수로 고정하고 모든 카메라의 raw-corner pixel 잔차를 하나의 벡터로 쌓아 카메라·손목·공유 target pose를 동시에 최적화합니다. 별도 e_cross loss를 더하는 방식이 아니라 공유 target pose가 카메라 간 피드백을 만듭니다.

아웃라이어: 본표 BA는 homography/RANSAC으로 corner를 삭제하지 않고 soft_l1, f_scale=2 px를 사용합니다. ChArUco 최소 4 corners, fixed cube 최소 8 corners, 손목 cube aspect gate가 frontend 고정 mask를 만듭니다. PnP RANSAC은 cube pose 초기화 경로에만 사용됩니다.

A5: train-only 6-DoF correction과 독립 label이 없어 실행하지 않았습니다. A4/B1/B2도 실측 covariance 대신 2 mm/0.3° Simulation prior를 쓴 preflight입니다.
