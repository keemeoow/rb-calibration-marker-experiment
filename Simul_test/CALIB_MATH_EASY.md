## 0. 딱 5개의 기호만 알면 된다

로봇 시스템에는 "좌표계(frame)"가 여러 개 있고, 캘리브레이션이란
**좌표계 사이의 변환(위치+회전, 4×4 행렬 T)을 알아내는 일**이다.

```
                ┌──────────────────────────────────────────────┐
                │                  Base (로봇 밑동)              │
                │   ▲                        ▲                 │
                │   │ bTg(e)  ← 로봇이        │ Y_i  ← ???      │
                │   │          알려줌(FK)      │      (미지수)    │
                │ Gripper(손끝)          고정 카메라 i            │
                │   │ X ← ??? (미지수)         │                 │
                │ 그리퍼 카메라                 │  O_i(s) ← 사진   │
                │   │ O_g(e) ← 사진에서 계산    │      에서 계산   │
                │   ▼                        ▼                 │
                │              큐브 (테이블 위 마커 상자)          │
                └──────────────────────────────────────────────┘
```

| 기호 | 뜻 | 어디서 오나 |
|---|---|---|
| `bTg(e)` | base → gripper (촬영 순간 e의 로봇 자세) | **로봇 FK가 알려줌 (상수)** |
| `X` | gripper → 그리퍼카메라 (hand-eye) | **미지수 ①** (eye-in-hand) |
| `Y_i` | base → 고정카메라 i | **미지수 ②** (eye-to-hand) |
| `O_g(e)` | 그리퍼카메라가 본 큐브 (사진 → PnP) | 관측 (사진마다 나옴) |
| `O_i(s)` | 고정카메라 i가 본 큐브 (set s에서) | 관측 |

변환은 화살표처럼 **이어 붙일(곱할) 수 있다**:

```
base에서 본 큐브 위치 = base→gripper → 카메라 → 큐브 를 쭉 이어 붙인 것
                    = bTg(e) · X · O_g(e)
```

### 모든 수식의 뿌리가 되는 물리 법칙 하나

> **"같은 큐브는, 어떤 카메라를 거쳐 계산하든, base 좌표계에서 같은 위치여야 한다."**

큐브가 set s 동안 안 움직였다면, base에서 본 큐브 위치를 `Cube_s`라 할 때:

```
그리퍼카메라 경로:   bTg(e) · X · O_g(e)  =  Cube_s     ...(식 1)
고정카메라 i 경로:        Y_i · O_i(s)    =  Cube_s     ...(식 2)
```

캘리브레이션 방법들의 차이는 결국 **이 두 식을 어떻게 푸느냐의 차이**다.

# Part 1. Separate vs 통합

## 1-1. Separate 방식 = 문제를 쪼개서 각자 따로 푼다

### eye-in-hand (X 구하기) — 고전 AX = XB

로봇을 자세 1 → 자세 2로 움직이면, "로봇이 움직인 양"과 "카메라 화면에서 타깃이
움직인 양"은 같은 움직임을 다른 좌표계에서 본 것이다. 그래서:

```
A · X = X · B

A = inv(bTg(1)) · bTg(2)        ← 로봇이 말해주는 그리퍼의 움직임 (FK)
B = O_g(1) · inv(O_g(2))        ← 카메라가 말해주는 타깃의 움직임 (사진)
X = 미지수 (hand-eye)
```

자세 쌍을 여러 개 모아 X를 푼다 (Tsai, Park 등 공식 존재 —
실제 코드의 `cv2.calibrateHandEye`, `jeus_charuco_calb/step4_axxb_opencv_depth.py`가 이 방식).

### eye-to-hand (Y_i 구하기) — 카메라마다 따로 또 AX = XB

고정카메라 i 앞에서 그리퍼에 타깃을 붙여 움직이면, 위와 똑같은 꼴의 방정식이
**카메라마다 하나씩** 나온다. 카메라가 3대면 문제 3개를 **각각 독립적으로** 푼다.

### separate의 수식적 특징 (= 한계)

```
문제 1:  X   만 나오는 방정식        ← 큐브식(식1)만 사용
문제 2:  Y_1 만 나오는 방정식        ← 카메라 1의 관측만 사용
문제 3:  Y_2 만 나오는 방정식        ← 카메라 2의 관측만 사용
  ...
```

- **미지수들이 서로의 식에 등장하지 않는다.** X를 아무리 잘못 구해도 Y_i 계산은
  그걸 전혀 모른다.
- 그래서 "식 1의 답과 식 2의 답이 같은 Cube_s를 가리키는가?"를 **아무도 검사하지 않는다.**
- 로봇 FK 오차, 카메라 노이즈가 각 답에 **그대로 남는다.** 서로 교정해 줄 통로가 없다.

> 비유: 학생 4명이 같은 문제를 각자 풀고 답을 맞춰보지 않는 것.
> 한 명이 실수해도 아무도 모른다.

## 1-2. 통합 방식 = "모두 같은 큐브를 보고 있다"로 전부 묶어서 푼다

식 1과 식 2를 **하나의 최소화 문제**에 넣는다. 큐브 위치 `Cube_s`도 미지수로 둔다:

```
     ┌ 그리퍼카메라 항: 사진마다  bTg(e)·X·O_g(e) 가 Cube_s 와 가까워야 함
     │
min  │  Σ  ‖ bTg(e)·X·O_g(e) ⊖ Cube_s ‖²     ← X 와 Cube_s 를 잇는 끈
X,Y_i,│ 
Cube_s│  Σ  ‖ Y_i·O_i(s)     ⊖ Cube_s ‖²     ← Y_i 와 Cube_s 를 잇는 끈
     └ 고정카메라 항: 카메라 i가 계산한 큐브도 같은 Cube_s 여야 함
```

(`⊖`는 "두 포즈의 차이(회전 각도 + 위치 거리)"라는 뜻의 잔차)

### 뭐가 달라지나 — 딱 한 가지, 그런데 결정적

**`Cube_s`라는 공유 미지수가 모든 항에 들어간다.** 그 순간:

- 카메라 1이 큐브를 조금 왼쪽으로 잘못 보면, 다른 카메라들의 항이 "아니, 큐브는
  여기야"라고 **잡아당긴다** → 노이즈가 평균으로 상쇄된다 (합의 효과).
- X가 틀리면 그리퍼 항이 Cube_s를 엉뚱한 곳으로 끌고, 고정캠 항들과 충돌한다
  → 이 충돌(잔차)이 X를 교정한다. **eye-in-hand와 eye-to-hand가 서로를 검증**한다.
- 답 전체가 자동으로 **하나의 일관된 base 좌표계** 안에 놓인다.

> 비유: 학생 4명이 풀이 과정을 맞춰보며 같이 푸는 것. 한 명의 실수를 나머지가 잡아준다.

### 실제 코드는 이걸 어떻게 구현했나 (Step3_calibration.py)

한 방에 큰 최적화를 돌리는 대신 같은 제약을 단계적으로 적용한다:

| 단계 | 하는 일 | 위 수식과의 대응 |
|---|---|---|
| STEP-C | `calibrateHandEye`로 X 초기값 + **cube 일관성으로 채점** | X 후보를 식1+식2 충돌량으로 평가 |
| HE-refine | board 잔차 + cube 잔차 **동시 최소화**로 X 다듬기 | 그리퍼 항 최소화 |
| STEP-D | `Y_i = 평균[ Cube(e) · inv(O_i(e)) ]`, Cube(e)는 그리퍼 경로로 계산 | 식2를 식1의 결과로 풀기 |
| 피드백 | 고정캠 합의로 만든 Cube로 그리퍼 쪽 FK 오차를 역보정 | 식1을 식2의 결과로 재교정 |

## 1-3. 한 줄 요약

```
separate:  min ‖X 식‖²   따로,   min ‖Y_1 식‖²  따로,  ...   (끈이 없다)
통합:      min [ ‖X 식‖² + ‖Y_1 식‖² + ... ]  공유 미지수 Cube_s 로 전부 연결
```

# Part 2. fixed-FK / no-FK / ours-A / ours-B

이제부터는 **전부 "통합" 틀 안에서의 이야기**다. 4방법의 차이는 단 두 가지 손잡이다:

> **손잡이 1 (λ)**: 로봇이 말해주는 큐브 위치(FK prior, `F_s`)를 얼마나 믿을까?
> **손잡이 2 (2차 보정)**: 캘리브가 끝난 뒤, 남은 오차를 한 번 더 학습해서 닦아낼까?

여기서 `F_s` = "로봇아, 큐브를 (x,y,z)에 놔" 하고 명령했을 때 로봇 FK가 주장하는
큐브 위치. 로봇 오차 때문에 실제 위치와 몇 mm 어긋날 수 있다.

## 2-1. 공통 목적함수 — 항 하나가 추가될 뿐

Part 1의 통합 목적함수에 **anchor(닻) 항** 하나만 추가된다:

```
min      Σ ‖ bTg(e)·X·O_g(e) ⊖ Cube_s ‖²      ← vision 항 (그리퍼캠)
X,Y_i, +  Σ ‖ Y_i·O_i(s)     ⊖ Cube_s ‖²      ← vision 항 (고정캠)
Cube_s + λ·Σ ‖ Cube_s ⊖ F_s ‖²                ← anchor 항: "큐브는 FK가 말한 곳 근처야"
```

λ는 "FK를 믿는 정도"를 조절하는 다이얼이다:

```
λ = 0        →  FK 완전 무시. 큐브 위치는 카메라들의 합의로만 결정.
λ = 0.5      →  카메라 합의가 주도하되, FK가 부드럽게 잡아당김 (soft anchor).
λ = ∞ (하드) →  Cube_s ≡ F_s 로 못박음. 큐브는 미지수에서 빠짐.
```

## 2-2. 네 방법 = 다이얼 두 개의 조합

| 방법 | λ (FK 믿음) | 2차 보정 | 한 문장 요약 |
|---|---|---|---|
| **no-FK** | 0 | ✗ | 순수 카메라 합의. FK는 초기값에만 |
| **fixed-FK** | ∞ (하드 고정) | ✗ | 큐브 = FK 값으로 못박고 나머지만 품 |
| **ours-A** | 0 | ✓ | no-FK + 사후 잔차보정 |
| **ours-B** | 0.5 | ✓ | soft anchor + 사후 잔차보정 |

```
 FK를 안 믿음 ◄──────────────────────────────► FK를 전적으로 믿음
   λ=0                    λ=0.5                     λ=∞
 no-FK, ours-A            ours-B                  fixed-FK
```

### ① fixed-FK (λ=∞): 못박는 순간, 통합이 separate로 무너진다 ★

`Cube_s`를 상수 `F_s`로 바꿔치기하면 목적함수는:

```
min  Σ ‖ bTg(e)·X·O_g(e) ⊖ F_s ‖²  +  Σ ‖ Y_i·O_i(s) ⊖ F_s ‖²
X,Y_i        (X만 들어있음)                (Y_i만 들어있음, 카메라별로 완전 분리)
```

**공유 미지수가 사라졌다.** 카메라 i의 항에는 Y_i밖에 없으므로, 이 문제는
카메라별로 뿔뿔이 흩어진다:

```
Y_i = argmin Σ ‖ Y·O_i(s) ⊖ F_s ‖²      (각 i 가 독립 — 사실상 separate와 동일!)
```

→ **fixed-FK에서는 통합으로 풀든 separate로 풀든 같은 답**이다. Part 1의 "합의 효과"가
전부 사라지고, 카메라 노이즈를 상쇄할 통로가 없어진다. 대신 FK가 정확하고 카메라가
완벽하면(계통노이즈 0) 기준점이 공짜로 생기는 셈이라 가장 유리하다.

### ② no-FK (λ=0): 카메라들의 순수 합의

anchor 항이 0이므로 Part 1의 통합 목적함수 그대로다. 큐브 위치는 오로지
"여러 카메라가 어디서 겹쳐 보이나"로 결정된다.

- 장점: FK가 아무리 부정확해도(예: 16mm 오차) 영향 없음.
- 약점 1: 카메라들의 **계통 오차**(intrinsic 오차, 왜곡, 검출 편향)는 평균해도 안 사라짐
  → 큐브 위치가 통째로 미세하게 밀린다. 잡아줄 기준(닻)이 없다.
- 약점 2: **큐브를 동시에 보는 카메라가 1대뿐이면 성립 불가.** 식
  `Y·O(s) = Cube_s`에서 미지수가 Y와 Cube_s 둘 다라 답이 무한히 많다
  (삼각측량 불가). 이때는 F_s를 외부에서 주는 fixed-FK가 사실상 유일한 해법.

### ③ 2차 보정 (ours-A/B의 "✓"): 남은 오차를 지도학습으로 닦기

캘리브레이션이 끝난 뒤에 하는 **후처리**다. 목적함수는 건드리지 않는다.

1. 캘리브된 카메라들로 큐브 위치를 예측: `p_s = median_i [ Y_i·O_i(s) 의 위치 ]`
2. train set에서 "FK와의 차이"를 위치의 함수로 회귀 (Ridge):

```
잔차(p) ≈ w0 + w1·p_x + w2·p_y        ← "작업공간 어느 쪽에서 얼마나 밀리는가"를 학습
w 는 train set 의 (F_s 위치 − p_s) 를 타깃으로 최소제곱 (λ_ridge = 1e-3)
```

3. 새(held-out) 위치 예측에 적용: `예측 = p_s + 잔차(p_s)`

직관: 카메라 계통 오차나 FK 잔차는 **작업공간 위치에 따라 서서히 변하는 편향**이라서,
1차 함수 몇 개로 근사해 빼줄 수 있다. FK는 여기서 **정답 레이블**로만 쓰인다
(예측 파이프라인 자체는 여전히 순수 카메라).

### ④ ours-A vs ours-B: 유일한 차이는 λ

```
ours-A = no-FK  (λ=0)   + 2차 보정
ours-B = soft   (λ=0.5) + 2차 보정
```

ours-B의 soft anchor는 하드 고정과 달리 **Cube_s가 여전히 미지수**라서 카메라 합의
효과가 살아 있으면서도, FK가 "너무 멀리는 못 가"라고 부드럽게 잡아준다.
→ 카메라 계통 오차로 합의 전체가 밀리는 것(no-FK 약점)을 FK 닻이 막고,
FK의 오차는 카메라 합의가 희석한다. **양쪽 오차를 서로가 견제하는 구조.**

## 2-3. 그래서 언제 누가 이기나 (시뮬 결과 요약)

`Simulation/WHICH_WINS_WHERE.md`의 36개 조건 전수 비교:

| 조건 | 승자 | 이유 |
|---|---|---|
| 카메라 완벽 + FK 정확 | fixed-FK | 공짜 기준점이 노이즈 0으로 들어옴 |
| 카메라 완벽 + FK 엉망(16mm) | no-FK | 못박은 닻 자체가 틀린 상황 |
| **카메라 계통노이즈 ≥1% (현실)** | **ours-B** | 닻(soft)과 합의가 서로 오차를 견제 |

- ours-A가 ours-B를 이긴 조건: **0개** — 약한 닻(λ=0.5)은 항상 안전하게 이득.
- 실제 카메라는 intrinsic·왜곡·검출 편향(계통 오차)이 반드시 있으므로,
  **현실 조건에서는 ours-B가 사실상 항상 최선**이다.

# 전체 한눈 요약

```
                     ┌── separate: 식마다 따로 풀기. 미지수 간 끈 없음. AX=XB × N개
 캘리브레이션 ────────┤
                     └── 통합: 공유 미지수 Cube_s 로 전부 연결. + anchor 항 λ‖Cube_s⊖F_s‖²
                              │
                              ├─ λ=∞  : fixed-FK  → 수식이 카메라별로 분리 = separate와 동일해짐
                              ├─ λ=0  : no-FK    → 순수 합의 (계통오차에 취약, 1캠이면 불가)
                              ├─ λ=0  +2차보정: ours-A
                              └─ λ=0.5+2차보정: ours-B  ← 현실 조건 최강
```

| | separate | fixed-FK | no-FK | ours-A | ours-B |
|---|---|---|---|---|---|
| 미지수 결합(합의) | ✗ | ✗ (분리됨) | ✓ | ✓ | ✓ |
| 큐브 FK prior (λ) | — | ∞ (하드) | 0 | 0 | 0.5 (soft) |
| 2차 잔차보정 | ✗ | ✗ | ✗ | ✓ | ✓ |
| 로봇 자세 FK `bTg` | 사용 | 사용 | 사용 | 사용 | 사용 (전 방법 공통, gauge) |
| 카메라 계통오차에 | 취약 | 취약(합의 없음) | 취약(닻 없음) | 부분 방어 | **강함** |
| FK 오차에 | 취약 | **가장 취약** | 무관 | 무관 | 희석됨 |

> 주의: "no-FK"라는 이름은 **큐브 배치 prior(`F_s`)를 안 쓴다**는 뜻이다.
> 로봇 자세 FK(`bTg`)는 4방법 모두 사용한다 — base 좌표계는 로봇을 통해서만
> 관측 가능하므로, `bTg`까지 없애면 어떤 방식으로도 캘리브레이션이 성립하지 않는다.
