# 멀티카메라 캘리브레이션 PPT 발표자 노트

발표 파일: `multi_camera_calibration_FK_methods.pptx`  
권장 시간: 15–20분

## 1. 제목

“오늘은 여러 카메라가 같은 큐브를 보았을 때, 각자의 좌표를 하나의 로봇 베이스 좌표로 합치는 과정을 설명드리겠습니다. 수학을 먼저 보여드리기보다 문제 상황에서 시작해 마지막에 세 FK 방식의 목적함수까지 연결하겠습니다.”

## 2. 같은 큐브, 다른 답

카메라별 측정값이 다른 것은 누가 틀렸기 때문이 아니라 각자 다른 원점을 쓰기 때문이다. 이 문제를 먼저 납득시키는 슬라이드다.

## 3. 캘리브레이션 정의

“캘리브레이션은 좌표계 사이의 관계를 찾는 과정입니다. 우리의 공통 언어는 로봇 베이스 좌표계입니다.”

## 4. 내부와 외부

내부 캘리브레이션은 카메라의 눈, 외부 캘리브레이션은 카메라의 위치와 방향이다. 본 발표는 외부 및 hand–eye가 중심이다.

## 5. 좌표계

각 물체에 XYZ 축이 붙어 있다고 상상하게 한다. 기호를 외우게 하기보다 B가 최종 공통 기준이라는 점만 먼저 강조한다.

## 6. 변환행렬

“T는 회전 R과 이동 t를 함께 저장합니다. 행렬곱은 이동 경로를 차례로 연결하는 연산입니다.” 4×4 계산을 직접 시키지 않는다.

## 7. 고정 카메라 경로

`베이스→카메라`와 `카메라→큐브`를 곱하면 `베이스→큐브`가 된다. 이 한 식이 전체 설명의 중심이다.

## 8. 그리퍼 카메라 경로

그리퍼 카메라는 움직이므로 베이스→그리퍼 경로가 하나 더 붙는다. `G_e`는 촬영 순간 로봇 FK로 알고 있지만, `X`는 hand–eye 미지수다.

## 9. Known / Unknown

세 FK 방식은 동일한 관측값을 사용한다. 달라지는 것은 set별 큐브 자세 `O_s`를 자유롭게 둘지, raw FK에 고정할지, 보정 anchor에 둘지다.

## 10. 합의

“같은 큐브를 봤으니 베이스 좌표로 옮긴 결과는 한곳에 모여야 합니다.” 최적화를 ‘점들을 한곳에 모으는 과정’으로 설명한다.

## 11. 상대 오차

본문에서는 `ε(A,B)=log(A⁻¹B)`라고 읽는다. 질문이 나오면 실제 구현은 상대 회전을 rotvec 3개로, 상대 이동을 3개로 꺼내 6차원 잔차를 만든다고 답한다. 완전한 SE(3) logarithm과 코드 구현이 미세하게 다르다는 점은 이 슬라이드의 하단 문구로 방어한다.

## 12. 세 FK 방식 개요

이 슬라이드에서 먼저 결론을 준다.

- No-FK: 안 믿기
- Fixed-FK: 그대로 믿기
- Corrected-FK: 고쳐서 적당히 믿기

세 방법 모두 관측식과 자세 오차는 같고 `Q_s`만 달라진다.

## 13. No-FK

최적화 변수에 `O_s`가 들어간다는 점을 가리킨다. no-FK라고 해도 촬영 순간 그리퍼 자세 `G_e`까지 버리는 것은 아니다. 큐브 FK prior만 사용하지 않는다.

## 14. Fixed-FK

`O_s=F_s`가 핵심이다. FK가 정확하면 미지수가 줄어 강한 기준이지만, FK가 틀리면 그 오차를 카메라와 hand–eye가 흡수할 수 있다.

## 15. Corrected-FK 직관

네 단계만 말한다: vision 1차 해 → 차이 계산 → 공통 보정 → 안전하게 혼합. 세부 gate나 SVD는 다음 슬라이드로 미룬다.

## 16. Corrected-FK 상세

현재 Step3형 구현과 대응한다.

1. 여러 카메라 예측의 robust set 합의 `V_s`
2. `Δ_s=F_s⁻¹V_s`
3. 관측 수 가중 robust 평균 `Δ̄`
4. `F_corr=F_sΔ̄`
5. 35 mm/8° gate
6. 통과한 경우만 alpha 0.25 blend
7. `A_s`를 사용한 최종 refinement

C1 Ridge `[1,x,y]`는 별도 출력 후보정이며 이 corr 정의에 섞지 않는다.

## 17. 통합 / 독립

통합은 하나의 공통 최적화, 독립은 subsystem을 따로 푼 뒤 정렬한다. FK 축과 solver 축은 서로 다른 실험 축이다.

## 18. 타깃 조건

보드는 평면, 큐브는 다면 3D 타깃이다. “둘 다”는 두 관측을 동시에 쓰는 조건이다. 보드에는 큐브 FK prior가 없으므로 board-only+fixed/corr는 정의하지 않는다.

## 19. 14개 조합

유효 조합만 세면 14개다. 이 표는 실험 설계 누락 여부를 설명할 때 사용한다.

## 20. 평가와 한계

시뮬레이션은 생성 GT가 있어 절대 오차를 계산할 수 있다. 실데이터 C1의 FK 대비 결과는 외부 물리 GT가 아니라 FK proxy 일치도다. “물리 정확도가 향상됐다”가 아니라 “FK proxy와의 불일치가 감소했다”고 표현한다.

## 21. 마무리

마지막 문장:

“세 방법의 카메라 관측식은 동일합니다. 다른 것은 공통 큐브 자세를 직접 찾는지, raw FK에 고정하는지, vision으로 보정해 사용하는지뿐입니다.”

## 예상 질문

### no-FK인데 왜 `G_e`를 사용하나요?

no-FK는 큐브 위치 prior `F_s`를 쓰지 않는다는 뜻이다. 움직이는 그리퍼 카메라를 베이스에 연결하려면 촬영 순간 로봇 그리퍼 자세 `G_e`는 필요하다.

### `log(A⁻¹B)` 내부는 모두 행렬인가요?

`A`, `B`, `A⁻¹B`는 4×4 변환행렬이다. 코드는 여기서 상대 회전행렬을 rotvec 3개로, 상대 이동을 3개로 바꿔 6차원 벡터를 최소화한다.

### Corrected-FK는 soft anchor인가요?

현재 Step3형 시뮬레이션에서는 vision과 corrected FK를 gate 후 alpha 0.25로 섞어 set anchor `A_s`를 만들고, 최종 refinement에서는 이를 고정 anchor로 사용한다. 과거 legacy soft-anchor 방식과 구분해야 한다.

### 실데이터에서 2–3 mm면 실제 정확도도 2–3 mm인가요?

아니다. FK cube center를 proxy로 사용한 결과라면 FK와의 agreement만 뜻한다. 외부 모션캡처나 정밀 측정기가 없으면 절대 물리 정확도로 표현할 수 없다.
