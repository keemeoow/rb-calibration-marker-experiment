# Zeus 캘리브레이션 파이프라인 시뮬레이션 결과 (`sim_pipeline.py`)

목적: (1) 노이즈 0에서 알고리즘 무결성 확인, (2) 어떤 노이즈에 어느 방식이 취약한지
요인별로 확인. 시뮬레이터는 `load_all_data()`와 똑같은 `data` 딕셔너리를 합성하므로
통합/독립/raw-fk solver와 모든 평가 코드가 그대로 돌아가고, 정답을 알기 때문에
카메라·`T_gripper_cam`·`T_gripper_cube`·큐브 pose의 **진짜 오차**를 잰다.

장면 정답은 실제 값에서 가져왔다(고정캠 extrinsics·gtc·grasp = `fit_통합_no-fk.json`,
보드 = 실측, 로봇 궤적 = session1/2/3 기록 그대로, K/D = intrinsics 파일). 합성
관측치 수 48/44/15/60/60 (실제 45/42/15/58/60).

표의 값은 seed 3개 평균. 스윕은 코너 검출 노이즈 0.3px를 기본으로 깔고 한 요인씩
올렸다. 계통 mm 오차에는 mm당 0.1°의 회전을 짝지었다. `cam mm` = 고정캠 3대의
정답 대비 평행이동 오차 평균, `gtc` = T_gripper_cam, `grasp` = T_gripper_cube,
`cube` = session2 큐브 pose(no-fk 계열만), `xview` = cross-view mean |e| px,
`camcom` = cam-common mm.

## 1. 무결성 — 노이즈 0

세 방식 모두 카메라·gtc·grasp·큐브 오차 **0.000**, train **0.000px**. 알고리즘과
데이터 배관에 결함 없음.

### 큐브 마커 기하 오차 (geom_sys_mm / geom_rand_mm)

| 계통 | 0.5 | 0.062 / 0.497 / 0.509 | 0.337 / 0.424 | 0.069 / 0.522 | 1.10 | 0.99 |
| 계통 | 1.0 | 0.062 / 0.997 / 1.008 | 0.692 / 0.846 | 0.069 / 1.021 | 1.10 | 0.99 |
| 랜덤 | 0.5 | 0.225 / 0.255 / 0.295 | 0.342 / 0.226 | 0.267 / 0.352 | 2.43 | 2.14 |

계통 오차(마커 전체가 한 방향으로 밀림)는 no-fk 계열에선 grasp·cube pose로 1:1
흡수되고 카메라는 무사; raw-fk는 카메라·gtc로 샌다. **마커별 랜덤 오차 1mm면
xview 4.6px / camcom 4.1mm — 실제 데이터의 4.7px / 4.2mm와 거의 같다.** 실제
카메라 간 불일치의 상당 부분이 큐브 마커 부착 오차(0.5~1mm)일 가능성을 시사.
GT 큐브에서 본 카메라별 편향과도 맞는 그림.

### session1 grasp offset 오차 (grasp_sys_mm)

no-fk/독립은 무영향(자기가 다시 추정). raw-fk만 앵커가 틀어져 카메라·gtc·grasp에
0.55 / 0.77 / 0.35mm(1mm 기준)로 들어간다.

### 코너 outlier (pixel_outlier_frac, 마커 단위 15px 오차)

통합은 soft_l1 덕에 카메라 오차 0.1~0.15mm로 버티지만, **독립의 그리퍼 그룹은
2%에서도 발산**(train 5.9e4 px) — 관측이 15장뿐이라 outlier 하나가 치명적.
그리고 cross-view/cam-common 지표는 단일 이미지 PnP에 robust 처리가 없어 outlier
한 개에 수백 px로 폭발한다 → 이 두 지표는 outlier 제거 후에만 의미 있음.

## 3. 결론

1. **무결성**: 노이즈 0에서 세 방식 다 정답 복원. 파이프라인 자체에 결함 없음.
2. **방식 간 차이가 나는 요인은 딱 셋**: 릴리즈 슬립·grasp 오차·큐브 기하 계통
   오차(→ raw-fk만 카메라로 샘), 세션 간 드리프트(→ 독립이 큐브에서 최악),
   outlier(→ 독립 그리퍼 그룹 발산). 나머지(FK 계통, 내부계수, 픽셀 노이즈)는
   세 방식이 똑같이 당한다.
3. **어떤 방식도 못 막는 것**: FK 계통 오차와 초점거리 오차. 둘 다 내부 지표로는
   안 보이고 정답 대비 오차로만 드러난다 — 외부 GT가 필요한 정확한 이유.
4. **실제 데이터의 카메라 간 불일치(4.7px / 4.2mm)** 는 픽셀 노이즈 0.3px로는
   설명이 안 되고(1.1px / 1.0mm), 마커 기하 랜덤 오차 ~1mm 또는 픽셀 노이즈 ~1px에
   해당한다. 큐브 마커 부착 정밀도 점검이 실측 개선 1순위 후보.
5. 값싼 개선 순서: (a) 내부계수 재검증, (b) 큐브 마커 기하 실측/재추정, (c) 카메라
   고정 상태 확인(드리프트), (d) 독립 그리퍼 그룹과 일치도 지표에 outlier 제거 추가.

## 4. 아직 안 넣은 노이즈 (후보)

우리 상황), 촬영 타이밍(sync) 오차(GELLO 이동 중 촬영), 렌즈 왜곡 계수(D) 오차,
